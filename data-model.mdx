The app consumes a JSON API that provides cruise ship schedule data for Eidfjord, Norway. All data is validated at runtime using Zod schemas.

## Ship type

The `Ship` type is the core data structure representing a single cruise ship visit.

**Location:** `src/state/Atoms.tsx:31`

```tsx
export type Ship = z.infer<typeof ship>
```

### Zod schema

The Ship schema is defined using Zod for runtime validation:

```tsx
const ship = z
  .object({
    day: z.string(),
    date: z.string(),
    anchorTime: z.string(),
    shipName: z.string(),
    tonnage: z.number(),
    length: z.number(),
    depth: z.string().or(z.number()),
    maxPassengers: z.number(),
    company: z.string(),
    agent: z.string(),
    fromPort: z.string(),
    toPort: z.string(),
    nationality: z.string(),
    dateOrdered: z.string(),
    notes: z.string(),
  })
  .strict()
```

<Note>
  The schema uses `.strict()` to ensure no additional properties are present in the data. Any extra fields will cause validation to fail.
</Note>

## Data validation flow

<Steps>
  <Step title="Fetch data">
    The `schedule` atom fetches JSON from the GitHub Gist

    ```tsx
    const res = await fetch(url).then((res) => res.json())
    ```
  </Step>

  <Step title="Parse with Zod">
    The response is validated against the `list` schema (array of ships)

    ```tsx
    const list = z.array(ship)
    return list.parse(res)
    ```

    If validation fails, an error is thrown and caught by React Query
  </Step>

  <Step title="Type-safe consumption">
    Components receive fully typed `Ship[]` data

    ```tsx
    const [shipList] = useAtom(selectedShipList)
    // shipList is Ship[] - TypeScript knows all fields
    ```
  </Step>
</Steps>

## Data transformations

### Date filtering

Ships are filtered by comparing the `date` field with the selected day:

```tsx
const selectedShipList = atom((get) => {
  const scheduleResult = get(schedule)
  
  if (scheduleResult.data && Array.isArray(scheduleResult.data)) {
    return scheduleResult.data.filter(
      (ship: Ship) => ship.date === get(selectedDay).format('DD.MM.YYYY')
    )
  }
  
  return []
})
```

**Format conversion:**
- `selectedDay` stores a Day.js object
- Formatted to `DD.MM.YYYY` to match the API's date format
- Case-sensitive exact match

### Anchor detection

Ships are identified as anchored by checking the `notes` field:

```tsx
const anchoredShip = ship.notes.toUpperCase().includes('ANKER')
```

**Behavior:**
- Case-insensitive check (converts to uppercase)
- Substring match ("ANKER" anywhere in notes)
- Affects ship card styling (color and icon)

## Error handling

<AccordionGroup>
  <Accordion title="Validation errors">
    If the API returns data that doesn't match the schema, Zod throws a validation error:

    ```tsx
    try {
      return list.parse(res)
    } catch (error) {
      // ZodError with details about which fields failed validation
    }
    ```

    React Query catches this error and exposes it via the `schedule` atom's error state.
  </Accordion>

  <Accordion title="Network errors">
    Network failures are handled by React Query:

    ```tsx
    const [scheduleResult] = useAtom(schedule)
    
    if (scheduleResult.error) {
      // Handle network error
    }
    ```

    The app uses Suspense, so these errors are caught by an error boundary.
  </Accordion>

  <Accordion title="Missing data">
    The `selectedShipList` atom safely handles missing data:

    ```tsx
    if (scheduleResult.data && Array.isArray(scheduleResult.data)) {
      return scheduleResult.data.filter(...)
    }
    return [] // Safe fallback
    ```

    This prevents runtime errors when data hasn't loaded yet.
  </Accordion>
</AccordionGroup>

## Best practices

<CardGroup cols={2}>
  <Card title="Always validate external data" icon="shield-check">
    Use Zod schemas to validate all data from external sources before it enters your application state.
  </Card>

  <Card title="Use strict schemas" icon="lock">
    The `.strict()` modifier ensures no unexpected fields are present, preventing subtle bugs.
  </Card>

  <Card title="Handle union types" icon="code-branch">
    Fields like `depth` that can be multiple types should use Zod's union types: `z.string().or(z.number())`
  </Card>

  <Card title="Provide fallbacks" icon="circle-exclamation">
    Always provide fallback values for optional or potentially empty fields to prevent rendering errors.
  </Card>
</CardGroup>
